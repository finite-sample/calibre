\begin{abstract}
Calibre combines probability calibration methods with tools for evaluating their accuracy, calibration, and effect on score ordering. Its common interface covers isotonic and centered isotonic regression, monotone splines, and methods that relax monotonicity. Evaluation includes proper scores, isotonic reliability diagrams and score decompositions, calibration-error estimators, and pointwise uncertainty bands. A reproducible comparison uses \BenchSynthetic{} synthetic designs and one real dataset across \BenchSeeds{} seeds. In the overconfidence design, centered isotonic regression retains an average of \CirDistinct{} distinct test predictions compared with \IsoDistinct{} for isotonic regression, with mean Brier scores of \CirBrier{} and \IsoBrier{}, respectively. Temperature scaling estimates the known probabilities more accurately in that design. These results illustrate why prediction granularity, calibration error, and predictive accuracy should be reported separately. Calibre's contribution is an implemented and tested workflow for making those comparisons; its methods do not guarantee better predictions or decision utility in every application.
\end{abstract}

\section{Calibration as a comparison problem}

Calibre lets researchers compare calibration maps using the same fitting interface and a common set of evaluation tools. A researcher can fit an isotonic map, replace it with centered isotonic regression or a monotone spline, and inspect changes in proper scores, reliability, and the distinctions between predicted probabilities. The software joins these operations without reducing their outputs to a single calibration verdict.

For a binary outcome $Y$, a forecast $P$ is calibrated when $\mathbb{E}[Y\mid P]=P$. A constant forecast at the population event rate can satisfy that condition while distinguishing no observations. Proper scoring rules evaluate both calibration and the information in a forecast \citep{degroot1983comparison,gneiting2007strictly}. Calibration error alone therefore cannot determine whether recalibration has improved predictions.

Isotonic regression illustrates the distinction. Pooling adjacent scores can remove noise but also assign the same forecast to observations with different input scores. Interpolating between pooled estimates can retain more distinctions, but those distinctions may not correspond to differences in event probabilities. Whether they help is an empirical question for observations not used to fit the map. Calibre reports distinct-value counts alongside proper scores and ranking measures so that retaining more values is not mistaken for improving predictions.

The contribution is software integration and validation. Centered isotonic regression, nearly isotonic regression, monotone spline bases, and isotonic reliability diagrams have established methodological sources \citep{oron2017centered,tibshirani2011nearly,ramsay1988monotone,dimitriadis2021stable}. Calibre supplies Python implementations or wrappers, shared numerical primitives, consistent input validation, and executable comparisons. It complements scikit-learn's calibration interface with these methods and evaluation tools \citep{sklearncalibration}. The benchmark below evaluates the implemented defaults, including their internal tuning, rather than claiming that one family dominates after an exhaustive search.

A deterministic map cannot separate observations that have exactly the same input score. \subsection{Isotonic and centered isotonic regression}

Weighted isotonic regression minimizes
\begin{equation}
\sum_{j=1}^{m}W_j(\bar y_j-z_j)^2
\quad\text{subject to}\quad z_1\leq\cdots\leq z_m.
\label{eq:iso}
\end{equation}
The pool-adjacent-violators algorithm (PAVA) solves this ordered problem in linear time \citep{ayer1955empirical}. Calibre's isotonic estimator wraps scikit-learn. Fitted values contain constant blocks; prediction interpolates linearly between fitted score knots.

Centered isotonic regression collapses a pooled block to a score anchor and interpolates between successive anchors \citep{oron2017centered}. Interior anchors are weighted score centroids. The implementation preserves flat boundary blocks at fitted probabilities zero and one, and holds endpoint values constant outside the anchor range. Centering is not a minimizer of Equation~\ref{eq:iso}. It imposes an interpolation assumption between pooled estimates, which can preserve distinctions without establishing that the underlying event probability varies within every block.

\subsection{Monotone splines and relaxed ordering}

The spline estimator fits
\[
\ell\{g(s)\}=\theta+\sum_{k=1}^{K}\delta_k I_k(s),\qquad \delta_k\geq0,
\]
where $I_k$ are non-decreasing I-spline basis functions and $\ell$ is the link. The default logit link uses penalized Bernoulli loss; the identity link uses penalized squared loss. A penalty on successive coefficient differences controls roughness. The basis and penalty follow established spline constructions \citep{ramsay1988monotone,eilers1996flexible}. Nonnegative coefficients guarantee a non-decreasing map, not a strictly increasing one. Cross-validation selects knot count and penalty before refitting on all calibration observations. The default scoring rule is log loss for the logit link and squared loss for the identity link.

Nearly isotonic regression replaces the ordering constraint with a penalty:
\[
\frac12\sum_j W_j(\bar y_j-z_j)^2
+\lambda\sum_{j=1}^{m-1}(z_j-z_{j+1})_+.
\]
Calibre implements the modified-PAVA solution path on the original penalty scale \citep{tibshirani2011nearly}. By default, cross-validation selects $\lambda$; the search holds the penalty per unit observation weight constant between training folds and the full fit. Finite penalties can reverse ranks. A small penalty can also fit outcome noise, so the existence of a nonmonotone population curve does not establish that the default estimator will recover it.

Relaxed PAVA instead imposes $z_{j+1}-z_j\geq L$, with a required, user-specified \texttt{min\_increment}. Zero recovers isotonic regression, negative values permit bounded decreases, and positive values require separation before clipping. The bound is per adjacent unique score, not per unit change in score. Appendix~\ref{app:shift} gives the reduction and its limitations.

\section{Evaluation and use}

\subsection{Proper scores, reliability, and granularity}

Calibre reports Brier score, $n^{-1}\sum_i(y_i-p_i)^2$, and supports logarithmic score in selection and decomposition. Lower scores are better. Its CORP reliability diagram fits isotonic regression of observed outcomes on forecast probabilities \citep{dimitriadis2021stable}. This evaluation fit is a diagnostic of the forecasts on the evaluation sample, not a new deployed calibrator. The CORP decomposition is
\[
\overline S=\mathrm{MCB}-\mathrm{DSC}+\mathrm{UNC},
\]
where MCB is the score reduction from isotonic recalibration on that sample, DSC is the improvement of those recalibrated forecasts over the sample event-rate forecast, and UNC is the latter forecast's score. These finite-sample components are not unbiased population quantities. Their identity is useful for understanding a score difference, but a small estimated MCB alone does not establish good predictive performance.

Granularity is the number or fraction of distinct forecast values. It is different from CORP discrimination and from AUC. A strictly increasing transformation preserves rankings and AUC; a non-decreasing transformation can introduce ties, and a nearly isotonic transformation can reverse rankings. The benchmark counts distinct values after rounding probabilities to six decimal places. The one-call report counts unique predictions under its own documented convention; users should state the convention when comparing counts.

\subsection{Calibration-error estimators and uncertainty}

Binned error depends on both the norm and the binning rule. Calibre's expected calibration error is an $\ell_1$ gap over uniform-width bins. Its plugin estimator allows a matched $\ell_2$ comparison on approximately equal-mass bins without splitting tied predictions. The debiased estimator subtracts a binomial variance term on the squared scale \citep{kumar2019verified}. Taking a square root after flooring at zero reintroduces bias near zero; the correction does not remove binning approximation error. The benchmark records this default nonnegative root, so it should not be described as an unbiased error estimate.

The monotonic sweep chooses a bin count using monotonicity of empirical bin event rates \citep{roelofs2022ece}. Its interpretation depends on a non-decreasing population calibration curve, an assumption deliberately violated by one benchmark design. Smooth calibration error uses kernel smoothing and an automatic bandwidth rule following the published reference implementation \citep{blasiok2024smooth}. These measures answer different questions and should not be ranked by their numerical size as though they shared one scale and construction.

The evaluation API provides pointwise consistency bands under the calibration null and pointwise confidence bands around a fitted CORP curve. The former simulate outcomes from the supplied forecast probabilities; the latter simulate from PAV-recalibrated probabilities and include a boundary correction. Both follow the resampling procedures associated with CORP \citep{dimitriadis2021stable}. Neither is a simultaneous envelope or a global calibration test. A separate bootstrap function estimates intervals for scalar metrics; such intervals condition on the supplied predictions and do not automatically include uncertainty from training the original model.

Plateau diagnostics describe score spans, calibrated values, and observation counts. Their support labels use conventional count thresholds. They do not test whether the population curve is flat, measure within-plateau discrimination, or justify breaking a tie.

Calibrators expose \texttt{fit(X, y, sample\_weight=None)} and \texttt{transform(X)}. Base-model scores used to fit a calibrator should come from observations excluded from that base model's training, and final evaluation should use a further held-out sample. \section{A reproducible comparison}
\label{sec:benchmark}

\subsection{Design and estimands}

The offline grid crosses \BenchSynthetic{} synthetic designs with an identity score model and the Wisconsin diagnostic breast-cancer dataset with logistic regression, a random forest, and histogram gradient boosting. The real dataset is distributed by scikit-learn; its positive label denotes benign cases \citep{breastcancer}. There are \BenchCells{} dataset/model configurations, \BenchMethods{} methods, and \BenchSeeds{} seeds, producing \BenchRows{} method-level records. The Calibre isotonic wrapper is included as an implementation check against scikit-learn isotonic, not as an independent competing algorithm.

% Generator constants below are definitions from benchmarks/datasets.py, not estimates.
In the overconfident, underconfident, and prior-offset designs, $Z\sim N(0,2^2)$ and the true probability is $\sigma(Z)$, where $\sigma$ is the logistic function. Reported scores are respectively $\sigma(1.8Z)$, $\sigma(0.6Z)$, and $\sigma(Z+0.8)$. The tied-score design rounds the overconfident score to two decimal places. The rare-event design draws $Z\sim N(-4.6,1.5^2)$ and reports $\sigma(1.6Z)$ for truth $\sigma(Z)$; it does not enforce a fixed prevalence. The small-sample design uses the overconfidence construction with 300 rather than 4,000 observations. The nonmonotone design draws $s\sim U(0,1)$ and clips $s+0.25\sin(2\pi s)$ to $[0.01,0.99]$ to obtain the event probability. All other synthetic designs have 4,000 observations per seed. Outcomes are Bernoulli draws conditional on these probabilities.

The benchmark holds out \BenchTestPercent\% of each dataset. For real data, \BenchFolds{} stratified folds within the fitting sample generate out-of-fold base-model probabilities. Preprocessing is fitted inside each fold. Calibrators fit those scores, and the base model is refitted on the full fitting sample before scoring the test sample. Thus calibration uses scores from somewhat smaller training sets than deployment; the experiment measures this particular workflow. Synthetic designs split the constructed scores directly. Within each seed and configuration, every calibrator receives identical inputs.

Comparators are uncalibrated scores, isotonic regression, logistic recalibration of log-odds, and temperature scaling. The logistic comparator uses scikit-learn logistic regression with a near-unpenalized fit to log-odds. The temperature comparator uses a bounded scalar optimization of log temperature. Neither calls \texttt{CalibratedClassifierCV}; scikit-learn's sigmoid wrapper instead uses the base estimator's decision function or probability output \citep{sklearncalibration}. Calibre's centered, spline, and nearly isotonic estimators run at library defaults. Both spline and nearly isotonic defaults include internal cross-validation, so tuning budgets differ. Relaxed PAVA and CDI-ISO require application-specific inputs and are not in this defaults-only grid.

Brier score and CORP miscalibration are the configured primary measures. Supporting measures include logarithmic score, AUC, granularity, and runtime. Plugin and debiased binned errors use \BenchBins{} requested equal-mass bins and the $\ell_2$ norm; sweep error also uses $\ell_2$. Mean absolute error against the generating probability is available only for synthetic data. With rounded scores, this is error against the latent individual probability, not the conditional mean given the coarsened score; some of it cannot be removed by any deterministic score map.

Each comparison subtracts a method's Brier score from isotonic's within the same seed. Positive differences favor the method. Intervals are percentile intervals from \BenchBootstrap{} bootstrap resamples of these \BenchSeeds{} paired differences. Synthetic seeds regenerate data; real-data seeds repeatedly split the same observations. The latter intervals describe split and algorithm variability conditional on this dataset, not uncertainty over independent datasets or clinical populations. The intervals are descriptive and are not adjusted for multiple comparisons.

\subsection{Accuracy and granularity need separate evidence}

Centered isotonic and the spline retain more distinct forecasts than isotonic in the overconfidence design, with lower mean Brier scores (Table~\ref{tab:overconfident}). Centered isotonic produces \CirDistinct{} distinct test values on average versus \IsoDistinct{} for isotonic. Their mean Brier scores are \CirBrier{} and \IsoBrier{}. This joint comparison supports a limited claim: under this design, retaining more distinctions need not worsen average held-out score. Their CORP miscalibration components are nevertheless larger than isotonic's: the lower Brier scores do not imply an improvement on every calibration diagnostic. \section{Validation, limits, and practical use}

Calibre's tests check numerical behavior independently of the manuscript. Committed R fixtures compare PAVA, centered isotonic regression, and the nearly isotonic path with reference implementations. Optimizer-based tests check constrained projections. Further tests check score identities, tie handling, fitted-estimator contracts, degenerate inputs, and plotting semantics. Smooth-error fixtures compare with the authors' reference software. Monte Carlo tests use known generating processes to examine bias and interval coverage in specified settings. Passing these tests establishes agreement on those cases, not universal finite-sample guarantees.

Every benchmark cell checks that Calibre's isotonic wrapper agrees with scikit-learn isotonic predictions to numerical tolerance. The manuscript generator requires the complete offline grid, rejects duplicate records, checks score decompositions, and generates tables and inline numbers from the raw results. A manifest records the input hash and benchmark environment. The paper build uses those results without downloading data or silently rerunning the grid. Appendix~\ref{app:reproduce} gives the commands.

The benchmark is deliberately limited. \BenchSynthetic{} synthetic mechanisms and one real dataset cannot establish a general ranking of calibration methods. The nominally matched defaults have different tuning costs, repeated splits are not independent datasets, and score granularity is not a utility measure. A scalar monotone map cannot repair all subgroup errors or recover distinctions absent from its input. The package's shuffled cross-validation and resampling tools also do not justify inference under temporal or clustered dependence.

For a new application, compare uncalibrated predictions and a simple parametric correction with flexible candidates on a proper score. Use centered isotonic when interpolation between pooled rates is a defensible assumption, and splines when a smooth monotone map is appropriate. Permit decreases only when that departure from ordering is substantively justified and improves validation performance. Examine reliability and ranking alongside the score, and reserve an untouched sample for the final comparison. A decision-utility claim requires explicit decisions, costs, and an evaluation at those operating conditions; none follows from preserving more probability values alone.

\section{Adjacent increment constraints}
\label{app:shift}

For sorted unique score groups with $W_j>0$, consider
\[
\min_{z\in\mathbb R^m}\sum_jW_j(\bar y_j-z_j)^2
\quad\text{subject to}\quad z_{j+1}-z_j\geq L_j.
\]
Set $R_1=0$, $R_{j+1}=R_j+L_j$, and $u_j=z_j-R_j$. The constraints become $u_{j+1}\geq u_j$ and the loss is $\sum_jW_j(\bar y_j-R_j-u_j)^2$. Thus one weighted isotonic projection gives $z_j=u_j+R_j$. This is the total-order cumulative-shift construction associated with margin-separated isotonic projection \citep{gunasekar2016preference}. The substitution supplies the proof directly; it is not evidence that any chosen bound improves calibration.

The projection takes $O(m)$ time once scores are ordered and ties aggregated. Sorting arbitrary observations generally takes $O(n\log n)$. The unbounded feasible set is nonempty for any finite $L_j$. Adding a probability box can make positive increment requirements infeasible: required cumulative increases can exceed one. Calibre instead solves the unbounded problem and optionally clips its result to $[0,1]$. Clipping preserves nonpositive lower bounds but can flatten positive increments, so the clipped output is not generally the constrained optimum with a probability box. Bounds on adjacent unique scores also do not establish a derivative bound between scores.

\section{Experimental cost- and data-informed isotonic calibration}
\label{app:cdi}

\texttt{CDIIsotonicCalibrator} constructs local bounds from repeated-score event rates and user-supplied thresholds. It is an experimental mapping rule, not a validated procedure for improving economic decisions. Thresholds and input scores must use the same probability-score scale; the kernel does not locate a threshold by inverting a fitted calibration map.

For normalized threshold weights $a_k$ and bandwidth $h$, the implementation uses
\[
e_j=\sum_k a_k\max\{0,1-|\tfrac12(x_j+x_{j+1})-t_k|/h\}.
\]
Within each unique-score group, Kish effective size is $n_j^{\mathrm{eff}}=(\sum_iw_i)^2/\sum_iw_i^2$. Adjacent groups define a pooled rate $\tilde p_j$, weighted by these effective sizes, and
\[
q_j=\sqrt{\tilde p_j(1-\tilde p_j)
\left(1/n_j^{\mathrm{eff}}+1/n_{j+1}^{\mathrm{eff}}\right)}.
\]
Writing $c=\Phi^{-1}(1-\alpha/2)$, the bound is
\[
L_j=\gamma e_j[\bar y_{j+1}-\bar y_j-cq_j]_+
 -(1-e_j)cq_j.
\]
The cumulative-shift solver then fits a right-continuous step map. Away from the supplied thresholds, the bound can be negative; the result need not be monotone. The clipping limitation in Appendix~\ref{app:shift} applies here too.

Most unique-score groups have size one when scores are continuous. A pooled normal approximation then provides weak evidence, especially near event rates zero and one. Effective sample size makes the calculation invariant to common weight rescaling but does not justify arbitrary sampling or importance weights as binomial replication. Thresholds, bandwidth, and the increment multiplier require application-specific validation. No independent reference implementation or decision-curve experiment is supplied by the current benchmark, so CDI-ISO is excluded from its comparative conclusions.

\section{Reproduction and software availability}
\label{app:reproduce}

The package and benchmark are available at \url{https://github.com/finite-sample/calibre}. Installation and the executable tutorials are documented at \url{https://finite-sample.github.io/calibre/}. The software uses the MIT license. The following commands install the locked environment, rerun the offline grid, rebuild its shared summaries, and compile this paper:
\begin{lstlisting}
uv sync --locked --all-groups
uv run python -m benchmarks.run --n-jobs 4
uv run python -m benchmarks.aggregate
make paper
\end{lstlisting}
\texttt{make paper} generates exhibits from the raw benchmark and uses \texttt{latexmk}; it requires a LaTeX installation. Its output is \texttt{ms/build/calibre.pdf}. \texttt{make paper-check} executes the example and the manuscript artifact tests. The benchmark environment stores versions, revision, and source hashes, including the lockfile. The generated manifest links that environment to the raw input hash. Changes to defaults require rerunning the grid before making new empirical claims.
